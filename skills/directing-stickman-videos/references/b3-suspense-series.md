# B3 original suspense series: production route

Use when the user requests repeatable original suspense episodes in B3. This route extends [B3](b3-television.md) and the [common production QA](autopilot-production-qa.md); it does not make the renderer an automatic writer, animator, composer or publisher. Read the [two-reference visual findings](b3-anomaly-reference-findings.md) before setting the style ledger.

For INDEX NINE's approved flat character sheet, use `assets/characters/index-nine-female-four-view.png` and `assets/characters/index-nine-male-four-view.png` as visual proportion targets. `scripts/b3-series-finish.mjs` applies the reusable `b3-lock-character-style.mjs` pass automatically; it locks every puppet to a solid white pictogram body with a thick near-black contour, complete legs, and a solid head. Set `characterGender: "male"` only for a male role; all other roles use the female silhouette. The sheets are references, not animated image rigs. The series checker enforces the locked puppet style when `series.character_style` is `solid_pictogram_v1`. Inspect custom path silhouettes separately, because the puppet lock cannot change those. Objects use gray base and white lit faces with thick dark contours. Never recolor actors gray to match props. Keep dark or medium-gray space directly behind a white actor; a white actor over a large white prop reads as a hollow outline even when the fill is correct. Inspect that contrast in the encoded frames.

## One episode, then a repeatable series

Choose one original account/series name before making a public cover or episode. Keep it in `series.channel_name`; keep the current case number in `series.file_number`. Use `scripts/b3-series-bug.mjs` (`makeSeriesBug` or `stampSeriesBug`) to place `FILE 053  //  CHANNEL NAME` at the upper left of **every story shot**, including cuts inside one episode. It is a small, low-contrast, screen-fixed archive identifier, not a title card or an extra cat logo. Set the identifier in 31-unit Inter with 5-unit tracking and dim gray; keep it visually quieter than the case title and captions. The story captions and large cards use the bundled rounded, heavy Nunito face: 50-unit captions with 1.5-unit tracking, widened 4% and flattened 10% in the renderer. Check the actual phone-sized line fit. Stamp story shots before appending the universal outro; put the full-screen opening fault above the identifier for its first eight frames. Increment the number for the next episode and pass `file_number + 1` to the universal outro's `NEXT FILE`. The same `channel_name` must appear on its transmission slate. A temporary working name is acceptable for a layout proof but must be replaced before publishing. Do not copy the reference account's name.

Plan chapters from story turns before drawing their progress boxes. For an 8–9 minute original suspense story, 7–9 chapters is a useful target, not a fixed quota: add a chapter only for a new question, clue, reversal or consequence. Store ordered `{shot,title}` starts in `series.chapters`. `scripts/b3-series-finish.mjs` now stamps both the file/channel identifier and `scripts/b3-chapter-progress.mjs` boxes on **every story shot**, including the chapter cards; the total comes from that episode’s actual chapter list and exactly one current box is filled. The first eight-frame signal fault covers the chrome. Run `b3-series-check.mjs` to catch missing or incorrect persistent boxes.

For this suspense-series visual direction, use neutral near-black space (`#020202`), bright clean white (`#FAFAFA`), warm yellow only where a physical light motivates it, and restrained danger red. Avoid the blue-black/gray-white wash of the first receipt draft. Treat the frame as a numbered anomalous-case file: a stable case ID, evidence pages, rule cards, and progress marks make each section feel like another part of a recovered record. Use a red dot only when it names a function or clue: REC status, the exact abnormal item on an evidence page, or a dangerous point in the scene. Keep fine frame-varying television snow faintly present across the whole film, including ordinary dialogue shots; it should read as a recorded signal without making faces, props or evidence text hard to read. Separate that bed from obvious horizontal-line, tear and RGB-breakup events. Open each episode in this anomalous-file series with an unmistakable full-screen signal seizure before the first case image or chapter card; the studied dog reference keeps heavy snow for frames 0–9 at 30 fps (about 0.33 seconds), then cuts cleanly into the story. At 24 fps, an eight-frame opening burst matches that duration. Reserve later 1–6-frame strong events for a contradiction, signal takeover or threat reveal. The two studied openings show two or three obvious interruptions in 25 seconds, but use the lower end when the story has fewer pivotal beats. Never schedule strong faults at a mechanical interval. Make a narrative scene push visibly readable, usually 6–10% over a 4–6-second shot, while holding the camera when evidence text needs careful reading. The same actor or prop must also move **within** the shot for a story reason; moving the whole camera is insufficient. Keep captions and status labels fixed while the scene pushes. Attach soft local glow to an actual light source (phone, window, door gap, screen, lamp) and confine the spill to its immediate surroundings; a global TV bloom is not motivated lighting. Use `b3-chapter-card.mjs` for a brief `FILE N` title and progress marker at each actual plot turn; it is a mini-chapter promise, not decoration every few seconds. Inspect the encoded 20–30 second A/B sample before rerendering a full episode.

Draw people and principal objects as solid white and gray shapes with a thick near-black outline. The default B3 puppet now has a filled head and outlined limbs/torso; use `headStyle: "outline"` only when that alternate look is explicitly intended. The recurring woman host uses the dedicated `b3-cat-archivist.mjs` portrait rig: a feline head without a large round muzzle, narrow eyes, short gray hair, a solid tailored human bust, and separately animated head and file hand. `b3-universal-outro.mjs` places her beside the institutional paw seal and the `DEPT. OF FELINE AFFAIRS / OPEN CASES DIVISION` label. Do not substitute the generic stick-limbed cat puppet for this identity frame. Use the selected female narration. Doors need visible panels, a handle, a physical gap/light source and a clear actor relationship. For native portrait framing, place door, person and evidence at deliberate depths rather than centering a tall blank rectangle. Check the silhouette at phone size. The cat archivist is a full character in the universal ending, not a small corner logo or a costume pasted onto the case protagonist. Give her a physical action and a close enough framing to read her head and hands on a phone.

Keep the series asset kit flat and economical: characters use a bright solid white body with a thick near-black outer contour; principal objects use a mid-gray base plus a distinct white lit face or highlight plane, with the same thick near-black contour. Do not flatten every prop to pure white. Reserve warm yellow for a motivated light source and red for a clue or danger signal. Avoid realistic material textures and painterly gradients. Reuse authored assets across shots, but animate position, scale, pose and occlusion for the story. Use detailed hand sprites only when a hand action is essential and individually approved. For this series, prefer a full-body pictogram figure, prop motion and evidence inserts; omit hand close-ups when they add cost or make the gesture ambiguous. If a pickup is shown, inspect frames before contact, at contact and after lifting: the object must visibly leave its source and remain attached to the hand. If the hand is omitted, cut from the object at rest to its evidence close-up without depicting a false pickup. When the user requests a 30-second approval gate, render and review that complete opening before producing or revising the full film.

1. **Idea and story.** Generate several premises, select one with a concrete visual mechanism, then write a complete original script with setup, escalation, reversal and consequence. Keep a premise log so later episodes do not recycle the same threat, prop or ending. A reference video's structure, plot, spoken text, character and soundtrack are study material, not reusable episode assets. Mark a few optional comic-release beats in the script using the beat contract below; each must have an actual setup and return to the threat.
2. **Voice and timing.** Confirm the authorized voice source and language. If using the user's recorded voice or a voice reference, keep its provenance and do not treat an earlier voice clone as permission to spend credits on a new generation. Make a short audition, check pronunciation, emotion, missing words and cut-off endings, then time captions and actions to the accepted recording. A placeholder voice may support a layout proof only; label it as such.
3. **Acting and staging.** Freeze each character's design, proportions and marks in a clean pose sheet. For every shot name the change in attention, posture, limb/hand placement, weight or physical contact. Show a before, transition and settled state for any action that drives the plot. Reject duplicate heads/limbs, detached hands, sliding feet, through-object intersections and repeated neutral presenters. Camera movement, a screen glow and caption turnover do not count as the actor's performance.
4. **Sound and music.** Write a cue sheet from the story and actual voice timings. Keep voice, ambience, Foley and score in separate stems. Make the score evolve with tension and location, reserve silence or dropout for motivated moments, and let small physical sounds establish the scene. A single loop under the whole episode, generic whooshes on cuts and soundtrack copied from the reference fail the music gate. Record origin and commercial-use rights for each external asset. Verify the final mix by listening and a small-speaker/mono check; meters alone are insufficient.
5. **Portrait edit and cover.** Recompose every scene for native 9:16 rather than cropping a 16:9 master. Keep the actor/prop action and captions inside phone-safe areas and check at actual phone size. Design a separate 1080×1920 cover: one decisive object/action, one clear threat, a short large title and enough contrast at thumbnail size. Verify text and focal detail after downscaling. Do not call an extracted frame a tested cover.

Build the cover with `python3 scripts/b3-cover-compose.py COVER_CONFIG.json OUTPUT.png` (requires Pillow). Give it a full-size `scene` PNG of **authored flat artwork only** and a config with `channel_name`, `file_number`, `headline_white`, `headline_red`, and `episode_title`. The default produces a 1080×1920 (9:16) full-video cover. For the TikTok profile tile, set `"format": "profile_grid_3x4"` in a second config and produce a separate 1080×1440 (3:4) cover; store its relative path as `series.profile_cover`. Keep the headline, face/figure, prop clue and brand tag inside that actual 3:4 composition; merely cropping the center of a finished 9:16 cover can cut off the hook or title. The compositor supplies the stable file tag, heavy rounded white/red hook, one red rule and lower title strip. Keep the hook to at most three white words and two red words; the red words must name the anomaly, not decorate a generic adjective. In the scene, use one readable white filled subject against a gray prop or setting, black field, heavy dark contours and one motivated light or red clue. Produce the story-specific scene art from that episode's assets; do not reuse another creator's character or cover wording. Save the scene PNG and both configs with the episode so either format can be rebuilt in another environment. Inspect the 270×480 full-frame reduction and the 270×360 profile-grid reduction; revise if the subject, clue or red word is unclear.

## Brief comic detours inside suspense

The recurring tone is a serious anomalous-case file that briefly loses its composure. A joke may momentarily step outside the immediate plot logic: a dry narrator aside, a bureaucratic label on an impossible event, a character's embarrassingly ordinary reaction, or a prop that behaves with absurd politeness. Then return to the danger. The dog reference does this with blunt administrative asides such as “That was unprofessional” and “It is no longer interested in your opinion”; study their **timing and function**, not their wording.

For an 8–9 minute script, first write the suspense without jokes. During revision, look for one to three places where the audience understands the threat well enough to enjoy a short detour. Do not force a beat into the opening hook, a rule reveal, a character's physical peril or the climax. Use this compact beat ledger alongside the shot ledger:

| Field | Required decision |
|---|---|
| setup | What serious expectation has just been established? |
| turn | What specific line, reaction or object action abruptly reframes it? |
| picture | What changes **within this shot** so the joke plays visually rather than in narration alone? |
| hold | Where is the short pause for recognition? Do not add a laugh cue. |
| return | What sound, action or new fact restores suspense immediately afterward? |

Example for an original receipt story: the witness form asks for the narrator's relationship to the missing person; they write “It's complicated”; the form silently stamps `SELF`; the narrator holds the pen for one beat; a second form prints with their handwriting already on it. This example illustrates the mechanism, not required dialogue or a reusable template. Check the complete scene with and without the detour. Keep it only if the joke is readable at phone size, earns a brief reaction, and makes the next threatening beat land harder. A random meme, repeated wink at the viewer, generic quip after every rule or joke that explains away the threat fails this gate.

## Ending the case file

Study the reference ending as a sequence of functions: a recurring official and institutional mark share an identity frame, a short signal fault, a brief seal-only hold, then a large final imperative and small next-file label. Keep the case-specific climax inside the episode. Then append the same **universal outro** to every episode using `makeUniversalOutro` in `scripts/b3-universal-outro.mjs`: a full-size female cat-headed archivist on a human body beside an original paw seal and `DEPT. OF FELINE AFFAIRS / OPEN CASES DIVISION` label, a dry fixed spoken sign-off, a three-frame signal fault, a seal-only hold, and a `LOOK AGAIN.` final card with a small paw print at its upper right. For a branded raster identity, pass the authored `identityImage` and transparent `headSideImage`, `headMidImage`, `headTurnImage` assets. The identity image displays before 2.2 seconds; the three isolated head poses then turn toward camera on a separate black close-up. Keep hands and body out of the head-pose assets so the head turn cannot deform a hand or create doubled ears. `scripts/b3-build-outro-project.mjs` builds a portable ten-second B3 outro project from an audio template. The channel name stays fixed across the series; only `NEXT_FILE` changes. Do not write case props, names or plot revelations into the reusable outro. Replace the local placeholder with the user's chosen female voice when available, aligning the two spoken caption cues to that recording. Review the archivist's head motion and the final card at phone size. This copies the reference's structural function, not its words, dog identity or artwork.

The B3 series runtime uses a 50 design-unit Nunito caption preset for phone readability; ordinary B3 projects keep their 34-unit Noto Sans preset. At a 360-pixel phone width this is about 14 pixels before device scaling. Check the encoded result at that size and split any cue that would wrap. This preset improves legibility but does not certify semantic grouping or sync.

For portable cutout acting, `node scripts/b3-acting.mjs specs.json layers.json` expands shot-local specifications into `puppet` layers with connected hands, independent joints, planted feet and a timed pose sequence. Each spec needs `id`, `action`, `reason`, `objective`, `x`, `y`, `scale`, `duration`; contact actions also need a visible world-space `target: [x,y]`. Supported actions are `notice`, `inspect`, `reach`, `take`, `offer`, `turn`, `step`, `recoil`, `point`, `write`, `pull` and `listen`. Keep `specs.json` and a shot ledger in the episode directory. A prop that is taken, turned or pulled must animate through the **same contact position and beat**; the rig does not move props for you. Stage the character large enough for the gesture to read at phone size. Inspect before/contact/after frames for each plot-changing action, including feet, occlusion and the next shot's starting state. Repeated neutral figures with a small head rotation fail this gate even when the renderer's pixel-motion check passes.

## Continuity as a production input

Before drawing repeated shots, make a `prop-continuity.json` ledger for **every story-critical recurring element**, not just paper: characters and clothing, keys, doors and room layout, disappearing objects, umbrellas, forms, screens, labels, and sound sources. Give each entity one identity, ordered shot appearances, a state at each appearance, and a story reason for each state change. A reappearance without a state change inherits its prior content and physical state. Name each continuous motion run (the same door closing, sheet advancing, battery draining or object crossing frames) and give its first and last value. A new copy or intentional reset needs its own identity or explicit story event. Put `series.prop_continuity` in the episode manifest as a relative path.

For an object that vanishes or returns, author a `presence` timeline in its track with the four explicit states `present`, `disappearing`, `absent`, `reappearing`. `presenceGroup(id, artwork, event, shotDuration)` from `b3-prop-continuity.mjs` turns the actual filled object artwork into an alpha-animated group when the scene pass is built. The next legal states are `present → disappearing → absent → reappearing → present`; a story can end during a transition. Never draw a dark rectangle over a prop to simulate disappearance. Set `coverage: true` on the track so any appearance omitted from its event/instance list fails before render; `forbid_cover_blocks: true` rejects old vanish-cover rectangles. Distinguish a staged text reveal from a fully visible prop state, including each child's `from` timing.

Use `node scripts/b3-prop-continuity.mjs PROJECT PLAN --repair` **before rendering**. It copies canonical artwork for repeated states and distributes a continuous motion over all shots in each declared run, then checks the result again. A one-shot run may set `hold_after` in seconds to finish a disappearance early and hold that state; give the next shot its own constant run. Top-level `absent_layers` rules remove unwanted duplicate objects from named shots, and `layer_properties` rules lock recurring prop geometry and colors. Follow with `node scripts/b3-series-check.mjs PROJECT`; edit the ledger or source artwork for any remaining semantic mismatch, rerun repair and check, and only render after both pass. A missed prop, wrong scene location or incorrect new story state cannot be fixed by interpolating keyframes: revise its authored state/source and rerun, rather than accepting a technical pass. After encoding, inspect a boundary sheet containing the last frame before and first frame after every tracked cut; repair and rerender any visible jump. Include the ledger, source artwork and repair script in the transferable episode package so this process runs outside the current chat.

For small profile figures, `makeSolidProfileActor` in `scripts/b3-solid-profile-actor.mjs` supplies one continuous filled head–torso–two-leg silhouette and a joined arm. Use it only where that full body remains visible at phone size; never represent a standing person with a circle and a short rectangle that omits the legs. Anchor a lean near the feet so the actor approaches a door lens without sliding its whole body through the door. Verify the eye reaches the lens, both feet remain on the room side, and the cut to the point-of-view shot follows that contact.

Run `node scripts/b3-acting-sheet.mjs PROJECT OUTPUT_DIR` to create before/contact/settle sheets for every actor shot. Review the sheets **and** the encoded transitions at normal speed. The sheets expose small actors, missing props, head collisions and misplaced feet; a sheet or joint-distance check cannot judge believable timing by itself.

## Full-length draft workflow

The user may request the complete 8–9 minute draft directly. Build the episode in a project directory that can be copied to another machine: keep `project.json`, narration, cover, script, score stems, ambience, Foley and any visual assets together, and use relative media paths. Do not make the episode depend on a chat transcript, one-off local path, or this repository's private test assets. The producer must author the story, poses, motion, sound and timing into the manifest; the renderer cannot invent them.

For generated narration, first make and audition one short raw sample in the selected voice. Check for overlapping voices, echo, artifacts, accent and pacing **before** ordering the rest of a long episode; ASR text matching alone cannot certify a clean recording. If that sample fails, repair or change the voice source before more paid calls. Then synthesize short story sections and transcribe **each actual audio result** before assembly. Compare it to the exact script: a successful generation job can still omit words or add nonsensical speech. Split and regenerate any failed section, then recheck it; do not pass a failed voice clip into the full film. `node scripts/b3-compact-voice.mjs INPUT.wav OUTPUT.wav [MAX_PAUSE_SECONDS]` trims only long silent spans and preserves the spoken sample rate. Fit the verified clips to authored chapter slots with pauses, not a blanket speed change. Re-align captions from the final assembled narration's word timestamps, then rerender and check the encoded film. Keep the source clips and assembly script in the episode package.

Choose the smallest repair scope from the actual changed inputs. A replacement narration or sound mix with **unchanged caption timings** keeps the cached picture clips: rerun `draft --replace`, verify `cache_hits` equals the shot count, and listen to the resulting mix. A caption timing change alters the burned-in picture for every shot whose cue overlaps that change; rerender those affected shot clips through the cache and reuse the others. A scene, actor, or prop change invalidates only shots containing that artwork, plus any continuity transitions that depend on it. Check the renderer's per-shot `cache_hit` output; if unrelated shots miss cache, investigate before continuing. Do not claim that an audio swap requires painting all shots again. `b3-append-outro.mjs` copies the already rendered story and outro video streams; when only their audio sample rates differ, it resamples the short outro audio to the story rate before concatenation. It rejects picture codec, size, frame-rate, or channel-layout mismatches instead of silently re-encoding the whole film.

## Failures found in the first full episode

Keep this as an executable repair loop for later episodes: record the exact shot/timecode, fix the **source state or input**, run its local check, inspect the encoded result, and repeat until the defect is gone. A passing JSON check alone does not close a visual defect.

| Observed failure | Owning input and repair | Required verification |
| --- | --- | --- |
| Milk vanished behind a dark rectangle and later returned with a black block | Author the carton as one `presenceGroup` with `present → disappearing → absent → reappearing → present`; remove cover-block layers. | Run `b3-prop-continuity --repair`, `b3-series-check`, then inspect the carton before, during, and after both events in encoded frames. |
| Receipt text or other recurring paper changed between cuts; a repair flattened a deliberate text reveal | Give every paper state an identity and reason in `prop-continuity.json`; preserve each child layer's `from` time for staged reveals. | Check boundary frames on both sides of every tracked cut and inspect the reveal mid-shot. |
| A background footprint or prop appeared twice | Declare the unwanted layer in `absent_layers` for that shot and repair the source composition. | Inspect the repaired shot and neighboring cuts at phone size. |
| Figure proportions, leg count, outline, or object fill drifted | Apply the approved solid pictogram actor template and gray-plus-white object palette at the scene-source pass; do not patch a single frame. | Run the series check and acting sheets, then inspect encoded ordinary and contact shots. |
| TTS returned success but spoke gibberish, omitted words, or inserted long silence | Transcribe each generated section, split/regenerate failed parts, and compact silence without speeding speech. | Compare actual ASR words with the script before assembly; listen to each repaired section. |
| A listener hears two overlapping voices or a voice-like echo, especially under the opening score | Treat the audible report as a failed mix. Isolate narration, score, ambience and effects. If the dry narration is faulty, replace that source; if it is clean, rebuild only the affected audio mix. Copy the encoded picture stream when captions are unchanged. Do not infer sound quality from the count of container audio streams or dismiss the report because the mix correlates with its narration source. | Audition the dry narration as an audio-only file, then the repaired encoded mix at normal speed and on a phone; check the transition back to music. Do not order replacement TTS until the dry-source check identifies the need. |
| Captions were visibly early or late after voice assembly | Align cues from the final assembled voice, then update only shots overlapping changed cues. | Inspect the first, middle, and last caption of each chapter against audio in the encoded film. |
| Story/outro concatenation failed despite matching picture | Match the short outro audio sample rate to the story using `b3-append-outro.mjs`. | Probe the final streams, check 8–9 minute duration, and full-decode the result. |
| Cover looked unlike the episode or had weak thumbnail hierarchy | Use `b3-cover-compose.py` with the approved flat scene, short heavy white/red headline, and phone-size review. | Compare the generated cover against the approved cover at actual thumbnail size. |

1. Run `node scripts/autopilot.mjs validate /absolute/project/project.json`, then `node scripts/b3-series-check.mjs /absolute/project/project.json`, and fix all structural errors. The series check requires 8–9 minutes, native 9:16, a separate 1080×1920 cover, a nonempty script, relative in-project narration/sound assets, at least two distinct timed score stems, story actions in at least half the shots, contact actions in at least 15% of shots, and `series: {title, script, cover, voice_status, acting_ledger}`. Every actor action needs an objective and story reason; puppet hands must reach their declared contact point. These are planning checks: inspect the rendered anatomy, actual prop contact and continuity. It reports `delivery_ready: false` until the human gates are reviewed. Check actual word alignment separately; a structural pass cannot establish it.
2. Run `node scripts/autopilot.mjs draft /absolute/project/project.json`. This renders the **whole** B3 story to `draft.mp4` and `draft-report.json` without creating an approval receipt. If the universal ten-second outro is rendered as a separate B3 project with the same codec, picture and audio layout, append it with `node scripts/b3-append-outro.mjs STORY.mp4 OUTRO.mp4 FILM.mp4`. This checks the resulting 8–9 minute duration and full decode. Reserve `render` for the separately approved film. `--replace` may overwrite a stale draft after an input change. B3 `preview --seconds N` also supports up to 180 seconds when a smaller diagnostic cut is useful.
3. Inspect the encoded opening, at least one ordinary middle passage per act, every plot reveal, every planned comic detour, the climax and the ending. For each detour verify the setup, visible turn, short hold and return at normal playback speed; cut it if it merely interrupts the threat. Listen to each score transition and the final mix; downscale the separate cover to phone thumbnail size. Log failures with exact timecodes, repair, rerender and repeat. The quality gate below applies to the full draft even when the pilot is skipped.
4. Package the project directory, draft, report, cover and a plain-language QA log. On another machine, install this Skill's declared runtime dependencies, run `validate`, and rerender from the same relative paths. A successful decode and motion report are technical evidence only; record visual, acting, music and caption review separately.

## Picture and sound quality gate

Record reference mechanisms observed, what was translated into this story, and what could not be compared. Check every shot for an identifiable focal subject, specific story action, clean character anatomy, readable props, caption sync and useful sound. Record failures with timestamps. If any reference-critical defect remains, label the draft failed and repair it before marking a full film accepted. A technical `validate` or MP4 decode pass does not establish aesthetic acceptance.

For automation, a scheduled task may begin only after one full episode passes those gates with the selected voice, soundtrack, cover and final review. The unattended workflow should generate a draft, run deterministic checks, save a review package and halt on an aesthetic/rights/voice uncertainty. Publishing requires a connected account and an approved publishing policy; a local render or queue receipt is not proof of a public TikTok post.
